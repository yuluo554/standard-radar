# 04 数据计划

> 阶段：M0 定稿 · 上游：data/README.md（数据源实测与合成纪律）、plan/01-题目文档.md §二·真值基准。
> 本文定义：数据资产分类、committed `data/` 布局与冻结纪律、真值基准口径、本地运行态 store 边界、M1 产出清单。
> 总纪律：**无出处不得以确定语气落库；合成样例一律标注为快照样本；真值库只存"输入与期望"，观测由引擎运行时实算。**

## 一、数据资产分类

| 类别 | 内容 | 入库（committed） | 冻结/台账 | 生成方式 |
|---|---|---|---|---|
| A. 真实捕获 raw | GB/HB 列表接口原始 JSON 响应（少量页，控体积）+ 元数据 | ✅ `data/snapshots/raw/` | sha256 台账 + `-text` 冻结 | 手动活网抓取（tools 脚本，M1） |
| B. 预置快照对 | "同一批标准的两轮快照"合成样本（受控） | ✅ `data/snapshots/pairs/` | 同上；标注"快照样本" | 确定性生成器（M1；禁随机/禁时钟） |
| C. 真值标注 | 对 B 的**人工标注期望**（哪些应判新增/字段变更/状态迁移/消失） | ✅ `data/fixtures/` | 同上；逐条可回溯 `std_id` | 生成器产骨架 + 人工核定（M1） |
| D. 订阅规则样例 | 示例订阅规则文件（假词样例） | ✅ `data/subscriptions.example.json`（M4 落位） | 普通文本（可改样例） | 手写 |
| E. 本地运行态 store | 每轮快照/事件流/raw 留证/日报产物 | ❌ 不入库（`.gitignore`） | — | 运行时产生 |
| F. 资产台账 | 全部入库数据资产的 sha256 与来源 | ✅ `data/assets-ledger.csv` | 即台账本体 | M1 生成 + 校验脚本复算 |

## 二、committed `data/` 布局（目标态）

```
data/
├── README.md                  # 数据源可获取性实测记录 + 合成数据纪律（已就位 v1）
├── assets-ledger.csv          # 资产台账：path, sha256, 来源, 抓取日, 说明（M1 落位）
├── snapshots/
│   ├── raw/                   # A. 真实捕获原始 JSON + *.meta.json（M1 落位）
│   └── pairs/                 # B. 预置快照对（R1/R2，标注"快照样本"；M1 落位）
├── fixtures/
│   └── truth-*.json           # C. 真值标注（输入=快照对引用；期望=事件集合；M1 落位）
└── subscriptions.example.json # D.（M4 落位）
```

`data/snapshots/**` 与 `data/fixtures/**` 在 `.gitattributes` 标 `-text`（**冻结半区**）：克隆后字节必须与提交时一致，sha256 台账复算必须相等。

## 三、冻结与台账纪律

1. **生成确定性**：合成数据生成器禁 stdlib `random`、禁 set 迭代序、禁系统时钟（需要"轮次时间"时写显式常量）；落盘 JSON 键序固定、缩进固定（如 `indent=2`、`ensure_ascii=False`、`sort_keys=False` 按显式键序）；
2. **再生成位级一致**：生成器提供 `--check` 模式（重新生成到内存并与落盘文件逐字节比对），作为守门测试/命令；「改体例 → 重新生成整目录」是唯一合法修改路径，**禁止手改冻结件**；
3. **台账复算**：`data/assets-ledger.csv` 登记每个资产 sha256；校验脚本（M1 落位）逐文件复算比对；克隆/检出后再跑一遍（验证 `-text` 生效、字节未漂移）；
4. **来源可溯**：A 类资产逐条记录 捕获 URL / 参数 / 时间 / HTTP 状态 / 耗时（`*.meta.json`）；数值口径与局限回写 `data/README.md`；
5. **计数对账**：捕获脚本记录接口 `total` 与实取条数并核对；未取全 → meta 显式 `truncated` 标记。

## 四、真值基准设计（零 API 依赖）

- **载体**：预置快照对（B）+ 真值标注（C）。构造"同一批标准的两轮快照"受控样本，人工标注：
  （M1 决策：真值载体扩为**三轮序列 R1/R2/R3**——去抖用例必须三轮表达；文件落 `pairs/` 保留 pair/R1-R2 视图 + 三轮序列文件，决策记录见 plan/06 M1 节）
  - 应判 `new` 的条目（上轮无、本轮有）；
  - 应判 `field_changed` 的条目与字段（含 `STATE` 迁移：如 即将实施→现行；`ACT_DATE` 调整；标准号版本）；
  - 应判 `disappeared` 的条目（含"连续 N 轮缺失才确认"的去抖用例：一轮缺失=不报、两轮缺失=报）；
  - **阴性用例**：两轮完全一致的条目（不该报的不报）——防误报的对照面；
- **口径定义**（写进 M4 基准 README）：
  - 检出率 = 正确检出的事件数 / 标注应报事件数；
  - 误报率 = 误报事件数 / 引擎全部上报事件数；
  - 分事件类型（new / field_changed / disappeared）分别统计；
- **只存输入与期望**：真值文件不含引擎输出（不存"观测值"快照）；读数时由引擎在内存中实算并与期望比对——防"比对两份预先算好的答案"式假绿；
- **采样声明**：真值基准是"受控样本上的规则验证"，**非穷举**；README/报告如实写"抽样覆盖"口径与样本数。

## 五、合成纪律（承接 data/README.md §四，补充细则）

1. 合成标准号**一律使用真实格式占位**（如 `GB/T XXXXX-YYYY`、`MH/T XXXX—YYYY`），并**标注为快照样本**；不得虚构真实标准号/名称/日期的对应关系；
2. 不得把推断值冒充标注真值；不得凭名称臆测状态或版本关系；
3. A 类真实捕获只用于字段核对与样例展示，**不参与真值基准的"应报事件"标注**（避免拿真实数据当"我以为的答案"）；
4. 冻结件修改 = 重新生成（见 §三），台账 sha256 三联动同步（生成器 / 台账 / 守门测试）。

## 六、本地运行态 store 与 committed data 的边界

| 落点 | 内容 | 入库 |
|---|---|---|
| `data/`（committed） | 预置快照对 / 真值 / 原始捕获留证 / 台账 / 样例规则 | ✅ |
| `stdradar_store/`（默认，`--store` 可改） | 每轮 live 快照、事件流、raw 留证、日报产物 | ❌（`.gitignore`：`stdradar_store/`、`reports/`、`snapshots/`） |

原则：**可复现的基准数据入库；可从数据源重建的运行态不入库**（体积随轮次增长）。

## 七、隐私与数据安全

- 仅标准**元数据**；不下载标准全文、不镜像详情页整页；
- 无遥测、不上传用户订阅规则与快照；
- 订阅规则可能含个人关注词 → 规则文件（`subscriptions.json`）在 `.gitignore` 中（不入库）；入库的只有假词样例 `subscriptions.example.json`。
