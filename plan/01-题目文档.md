## 一、项目介绍

国家标准与行业标准是企业经营的硬约束：产品能不能上市、能不能投标、能不能通过检测，取决于所引用的标准是现行、即将被代替还是已废止。标准信息集中发布在**全国标准信息公共服务平台**（std.samr.gov.cn），提供 GB 国家标准与 HB 行业标准两个库；平台自身有列表页与详情页，但**没有订阅、没有变更提醒**，用户只能靠自己反复翻页。

用户真实痛点是三条：**①翻不过来**——国标库总量达数万条、行标库更多，按发布日期倒序逐页翻找"我这行有没有新标准"成本极高；**②状态看不穿**——一条标准今天"即将实施"、明天"现行"、后天"被代替"，这些迁移散落在列表字段里，人工对不上；**③倒计时无人提醒**——"即将实施"的标准有明确的实施日期（`ACT_DATE`），企业若在实施日前没完成适配就是合规风险，但没有工具替你数日子。

开源侧目前**"国内标准变更监控 / 雷达"类项目空白度极高**（基准日 2026-10-15，GitHub 检索，见 §五锚点表）：10+ 条中文与英文检索式中，"标准 雷达 更新"、"标准 更新 监控 雷达"、"标准 爬虫"、"GB standard"、"国标 查询 工具"、"标准 合规 变化 追踪" 等**几乎全 0 相关**；命中的少数仓库（"国家标准 查询 库" 9 个、"行业标准 查询" 2 个）均为**查询/问答类**，做的是"查一条标准是什么"，**不是"盯一个领域变没变"**——变更监控与查询是两个问题。商业侧标准平台的付费推送服务主要面向大型企业，个人/中小企业缺乏轻量本地方案。

**数据底座是本题的确定性优势**：全国标准信息公共服务平台提供**免鉴权、JSON、可翻页、关键词可搜、实测无频率限制**的 GB/HB 双库接口（详见 `data/README.md` 实测记录），是少数"干净结构化 + 无鉴权墙"的官方数据源。

## 二、任务要求

> 首期模块限定为 **5 个**，数据源首期限定 **2 库**（GB 国标 + HB 行标）。全部模块遵循"**未挂原文核对不得落库 / 不得生效**"的确定性纪律：任何进入日报的条目，其状态与日期字段必须来自平台接口原文并可回溯到 `id`；接口未返回或无法核对的字段一律标 `pending`，不臆测、不用 LLM 猜。

### 1）GB / HB 双源抓取与统一 schema（数据底座）

- **输入**：GB 列表接口 `https://std.samr.gov.cn/gb/search/gbQueryPage?pageSize=N&pageNumber=M`（JSON，实测 `total=79826`）、HB 列表接口 `https://std.samr.gov.cn/hb/search/hbPage?pageSize=N&pageNumber=M`（JSON，实测 `total=119169`）；
- **输出**：两库归一后的统一标准条目模型（`std_id` / 标准号 / 中文名称 / 标准性质 / 发布日 `ISSUE_DATE` / 实施日 `ACT_DATE` / 状态 `STATE` / 归口或主管部门 / 库来源 `GB|HB`）；
- 每库一个独立适配器（字段名不同：GB 用 `C_STD_CODE`/`C_C_NAME`，HB 用 `C_STD_CODE`/`C_C_NAME`/`CHARGE_DEPT`/`STD_LEVEL`/`STD_CATEGORY`），适配器间不共享字段假设；某库失败**隔离不中断**（超时/非 200/解析失败单列原因码，不影响另一库本轮产出）；
- **确定性纪律**：字段映射与接口字段一一对应，映射不出的条目整条跳过并记录，不做启发式补全；请求带限频与 User-Agent 标识；翻页上限与页大小（`pageSize` 实测上限 500）作为设计决策一处定义，不写会漂移的硬承诺。

### 2）快照存储 + 变更 diff（招牌模式，核心）

- **输入**：本轮条目集与上一轮持久快照；**输出**：对同一 `std_id` 的 diff 报告——**新增标准**（上轮无、本轮有）、**字段变更**（状态/实施日/标准号版本等）、**消失条目**（上轮有、本轮未见）三类事件；
- 快照按轮次持久化（本地存储），变更历史逐轮累积，可查询任意 `std_id` 的变更时间线；
- **确定性纪律**：diff 判定基于**字段级比较**（非整条哈希一票否决）；由于接口**无日期区间参数**（见 `data/README.md` 局限），"变更检测"必须靠"上次快照 vs 本轮快照"完成——这正是本模块存在的理由；消失判定须连续 N 轮缺失才成立，避免网络抖动误报。

### 3）标准号版本解析（新旧版本归并）

- **输入**：标准号字符串（如 `GB/T 48222-2026`、`MH/T 1090—2026`）；**输出**：解析后的结构 `(代号, 顺序号, 年份)` 与**同标准号前缀的版本序列**（同代号+顺序号、年份不同 → 视为同一标准的新旧版本，年份大者为新）；
- 覆盖实测中出现的两类分隔符差异（`-` 与全角 `—`）与多种写法（`MHT 1090—2026` / `MH/T1090—2026` / `MH/T 1090—2026` 指同一标准）；
- **确定性纪律**：解析规则与真实格式一一对应；解析失败的标准号原样保留并标 `pending`，不做模糊匹配猜测版本关系；版本归并结论必须可由标准号字符串复算。

### 4）STATE 迁移检测 + "即将实施"倒计时

- **输入**：同一标准的历史状态序列与本轮 `STATE`/`ACT_DATE`；**输出**：状态迁移事件（实测平台状态取值含 `即将实施`、`现行` 等，迁移方向如 即将实施→现行→被代替/废止）与**"即将实施"倒计时**（相对 `ACT_DATE` 的剩余天数，用于合规预警）；
- **确定性纪律**：状态取值以接口原文为准，**不推断平台未返回的状态**；倒计时基于 `ACT_DATE` 原文计算，缺 `ACT_DATE` 即不生成倒计时（标 `pending`）；日期缺失或格式异常不得默认填充。

### 5）关键词订阅规则 + 中文日报生成

- **输入**：变更事件流 + 用户订阅规则文件（多关键词 + 排除词，如 `人工智能` 命中 / 排除某些非关注类目）；**输出**：中文 **Markdown / HTML 日报**（本地文件），按"新增 / 即将实施倒计时 / 状态迁移"分组，每条附标准号、名称、来源库、状态与实施日；
- 关键词过滤在本地完成，订阅规则文件化、可版本管理；实测平台 `searchText=<关键词>` 可用（GB `人工智能` 返回 114 条、HB 返回 113 条），但**首期不依赖服务端搜索**，以"快照 diff + 本地关键词过滤"为准，保证结果可复现；
- **确定性纪律**：同一事件在订阅规则不变时要么稳定命中要么稳定不命中；日报条目必带标准号与来源库，不夹带未核对字段；输出附"**以平台标准原文为准**"免责声明。

### 真值基准（零 API 依赖）

- **预置快照对 + 植入真值**：构造"同一批标准的两轮快照"受控样本，**人工标注**哪些条目应判为"新增"、哪些应判为"状态迁移"（标注对象为公开接口字段），验证检出与不误报；
- **合成样例纪律**：合成样例的标准号一律使用**真实格式**（如 `GB/T XXXXX-YYYY` 占位）但**标注为快照样本**，不得虚构真实标准号/名称/日期的对应关系；不得把推断值冒充标注真值。

### 扩展项（不计入首期 DoD）

详情页"代替 / 被代替"关系解析（实测详情页 `gbDetailed?id=…` 含"归口单位 / 中国标准分类号 / 国际标准分类号 / 代替 / 被代替"字段）、地方标准库（实测 `db/search/dbPage` 当前 `total=0`，通道暂无数据）、定时调度（本地 cron / 计划任务）、webhook 推送。

### 合规注意

遵守平台 robots 与访问频率；仅抓取标准**元数据**（标准号/名称/状态/日期/归口），不下载标准全文、不镜像详情页整页；抓取行为带明确 UA 标识可被识别与联系。

## 六、边界与非目标

- **不做**：**不做标准全文下载**（仅元数据 + 变更提醒）；不做付费标准获取/代购；不承诺覆盖全部标准库（首期仅 GB + HB 双库）；不做"标准解读"（只做变更提醒，避免误导——解读需专业资质，本工具不越界）。
- **隐私红线**：**纯本地运行，无遥测**；不上传用户订阅规则与快照；不采集任何个人信息。
- **合规红线**：遵守平台 robots 与限频；抓取器 UA 自标识；输出免责声明——变更提醒与倒计时**以平台标准原文为准**，不构成合规/法律意见。
- **品牌隔离**：不复制姊妹项目代码；文档不提其余项目业务领域。
- **首期范围限定**：5 模块 + 2 库；详情页"代替/被代替"关系、地方标准、定时调度、webhook 均为扩展项，不计入首期 DoD。
- **数值口径**：本文档出现的接口总量（GB `79826` / HB `119169`）与关键词命中数均为**基准日 2026-10-15 实测快照值**，随平台数据增长必然变化，**仅作可获取性证据，不作交付承诺**；首期"5 模块 / 2 库"为**设计决策**，一处定义（本文档 + `plan/00`），不做会漂移的硬数字承诺。
