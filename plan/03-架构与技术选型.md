## 一、架构总览

单进程、批处理式、纯本地的流水线架构；每一环的产物都落盘（可检视、可回溯、可复现）：

```
                    ┌───────────────────────────────────────────────────────────┐
                    │                    一轮 = 一次运行（可定时触发）              │
                    └───────────────────────────────────────────────────────────┘
  fetch            normalize         snapshot           diff              derive            report
┌────────┐      ┌────────────┐    ┌────────────┐   ┌────────────┐   ┌───────────────┐   ┌──────────┐
│ GB 适配 │──┐   │            │    │  持久快照   │   │ 字段级 diff │   │ 版本归并       │   │ 订阅过滤  │
│ (gb.py) │  ├──►│ 统一 schema │──► │ 轮次 R####  │──►│ 新增/字段   │──►│ 状态迁移       │──►│ 日报生成  │
│ HB 适配 │──┘   │ models.py  │    │ snapshot.py│   │ 变更/消失   │   │ 倒计时         │   │ report.py│
│ (hb.py) │      │            │    │ 事件流 jsonl│   │ diffing.py │   │ states.py     │   │ MD/HTML  │
└───┬────┘      └────────────┘    └────────────┘   └────────────┘   └───────────────┘   └──────────┘
    │ raw JSON 留证（sha256 台账）                    ▲                     ▲
    │                                                 │                     │
  限频/UA/超时/重试/翻页上限                     上一轮快照 ────────────────┘（stdno.py 解析在 derive 前置）
  失败隔离（单库故障不中断另一库）
```

分层约定：

- **适配层**（adapters/）：只做"取数与字段映射"，不含判定逻辑；每库独立、字段假设不共享；
- **模型层**（models.py）：两库归一后的唯一数据结构（schema 单一来源），快照/事件/报告全部消费它；
- **存储层**（snapshot.py）：轮次快照 + 追加式事件流；所有的"历史"都从这里读；
- **判定层**（diffing.py / stdno.py / states.py）：确定性规则，无网络、无随机、无时钟（时钟以参数注入）；
- **输出层**（subscribe.py / report.py）：本地过滤 + 双格式渲染（单一渲染源）；
- **入口层**（cli.py / __main__.py / compat.py）：参数解析、编码守卫、退出码契约。

## 二、关键流程详设

### 2.1 抓取（M2；adapters/）

- 请求：`GET` 列表接口（GB `gbQueryPage` / HB `hbPage`），参数 `pageSize`、`pageNumber`（+可选 `searchText`，首期不用）；JSON 免鉴权（实测见 data/README.md）；
- 请求纪律（常量集中于 adapters/base.py，"一处定义"）：
  - UA 自标识：`standard-radar (+https://github.com/yuluo554/standard-radar; local research tool)`；
  - 最小请求间隔 `MIN_INTERVAL_S`（默认 1.0s）、超时 `TIMEOUT_S`、有限重试 `RETRIES`（指数退避）；
  - 翻页上限 `MAX_PAGES_DEFAULT`；页大小 `PAGE_SIZE`（实测上限 500）；
- raw 留证：每个响应落盘 `store/raw/R####/<lib>-p<N>.json`，meta 记录 URL/参数/HTTP 状态/耗时/抓取时间/sha256；
- **对账纪律**（防"自洽但缺记录"的快照）：分页抓取时记录接口 `total` 与实取条数并核对（"页数×每页≥total 且最后一页非空"；未取全时在轮次元数据里显式记录 `truncated: true` 与原因）；关键请求参数回读验证（响应里的 pageSize/pageNumber 与请求一致）；
- 失败隔离：单库超时/非 200/解析失败/映射失败 → 该库本轮记 `{lib: {ok: false, reason: REASON_*}}`，另一库照常产出；两库全失败才整轮失败（exit 1）；
- 字段映射：逐一对照接口字段（GB：`id/C_C_NAME/C_STD_CODE/STD_NATURE/ACT_DATE/STATE/ISSUE_DATE/PROJECT_ID`；HB：`id/C_STD_CODE/C_C_NAME/CHARGE_DEPT/STD_LEVEL/STD_CATEGORY/ICS_NAME1_FULL/SYS_INPUTIME/STATE/ACT_DATE/ISSUE_DATE`）；映射不出的条目**整条跳过并记录**（REASON_MAPPING + 原因明细）。

### 2.2 快照存储（M3；snapshot.py）

本地 store（默认 `./stdradar_store/`，`--store` 可改；不入版本库）：

```
stdradar_store/
├── meta.json                  # store 版本与说明（M3 定稿）
├── snapshots/
│   ├── R0001.json             # 每轮一个快照文件（归一化条目集 + 轮次元数据）
│   └── R0002.json
├── events/
│   └── events.jsonl           # 追加式变更事件流（逐轮累积；每行一个 DiffEvent）
└── raw/                       # 原始 JSON 留证（按轮次子目录）
    └── R0002/gb-p1.json ...
```

- **轮次标识**：递增序号 `R0001…`（不是时间戳）；抓取时间、来源、参数、计数、截断标记等存储于轮次元数据（`meta` 字段）内。合成（预置）快照对同样用 `R1/R2` 口径（M1 冻结具体格式）；
- 快照文件为**归一化后的条目集**（std_id → StandardEntry），键序固定（`to_dict` 单一来源）→ 同输入生成字节稳定；
- 事件流 append-only：`diff` 每轮把新事件追加进 `events.jsonl`，绝不改写历史行；时间线查询 = 过滤该文件（`std_id` 回放）；
- 损坏防护：加载时校验文件 schema 版本与 json 可解析；坏轮次显式报错（不静默跳过）。

### 2.3 字段级 diff（M3；diffing.py）

- 对齐键：`std_id`；对比字段白名单：`std_code / name_cn / nature / state / act_date / issue_date / dept`（逐字段比较，**不是整条哈希一票否决**——整条哈希只会说"变了"，说不出"哪变了"）；
- 三类事件：
  - `new`：上轮无、本轮有（首轮快照 = 全部为 new？**否**——首轮只建立基线，不产生 new 事件；从第二轮起才有事件，首轮行为写进 M3 用例）；
  - `field_changed`：同 `std_id`、字段级差异（含状态迁移、实施日调整、标准号版本等）；
  - `disappeared`：上轮有、本轮未见；**去抖**：连续 `MISSING_DEBOUNCE`（默认 2）轮缺失才确认；中间轮记为"待确认缺失"（pending_disappeared），恢复出现则撤销；
- 不误报纪律：两侧值任一为 `pending`/缺失时不得直接判"变更"（M3 定稿细则：记录为 `field_changed(uncertain)` 或跳过 + 原因码，具体形态 M1 用真值用例定）；
- 事件对象统一用 `models.DiffEvent`；判定函数纯函数（输入两轮条目集 + 历史缺失计数，输出事件列表），无 IO。

### 2.4 标准号解析与版本归并（M3；stdno.py）

- 解析目标：`(代号, 顺序号, 年份)`；写法归一：分隔符 `-`（半角）与 `—`（全角）等价；代号内部空格/斜杠差异归一（`MH/T 1090—2026`、`MHT 1090—2026`、`MH/T1090—2026` 指同一标准）；
- 归并：同（归一化代号, 顺序号）、年份不同 → 同一标准的版本序列，年份大者为新；输出旧→新序列（结论可由字符串复算）；
- 纪律：解析失败的标准号**原样保留并标 pending**，不做模糊匹配猜测版本关系；模板已实测的真实格式：`GB/T 48222-2026`、`MH/T 1090—2026`。

### 2.5 状态迁移与倒计时（M3；states.py）

- 迁移检测：同一 `std_id` 的历史状态序列（从快照轮次读）→ 相邻轮状态不同即一条迁移事件（方向与取值以接口原文为准；**不推断平台未返回的状态**，如"被代替"仅当原文出现才算）；
- 倒计时：`countdown_days(act_date, today=None)`——`today` 可注入（测试确定性）；缺 `ACT_DATE` 或解析失败 → **不生成倒计时**（pending），不默认填充；
- 上报形态：进入日报"即将实施倒计时"分组的是：`state == '即将实施'`（原文）的条目，附剩余天数；剩余天数 ≤ 阈值（M4 定，默认 30 天，一处定义）时高亮提示。

### 2.6 订阅与日报（M4；subscribe.py / report.py）

- 订阅规则文件（JSON，本地可版本管理）：

```json
{
  "version": 1,
  "groups": [
    {"name": "我关注的方向", "keywords": ["人工智能", "信息安全"], "exclude": ["术语"]}
  ]
}
```

  - 命中规则：条目中文名称（+标准号）命中任一 `keywords` 且不含任一 `exclude` 词即命中；规则不变时**稳定命中/稳定不命中**（纯子串匹配，大小写按原文；全角/半角不做魔法转换——M4 定稿细则）；
- 日报：先聚合成**中间报表模型**（分组：新增 / 即将实施倒计时 / 状态迁移），再由**单一渲染源**输出 Markdown 与 HTML 两个格式（结构一致是机制保证，非人工比对）；HTML 自包含内联样式、**零外链**（断网可开）；
- 每条必带：标准号、名称、来源库（`GB|HB`）、状态、实施日；**不夹带未核对字段**；页尾固定"以平台标准原文为准"免责声明。

## 三、技术选型与否决项

| 决策点 | 选型 | 理由 | 否决项（及理由） |
|---|---|---|---|
| 语言/版本 | Python，底线 3.8，CI 矩阵 3.8 + 3.12 | 本机双通道实测可覆盖；跨版本差异交由 CI 暴露 | 只保 3.12（放弃 3.8 用户）；用 3.9+ 语法糖（3.8 直接跑不了） |
| 运行时依赖 | **零第三方**（`urllib`/`json`/`argparse`/`dataclasses`） | 免依赖 = 免安装事故；pip 环境不稳时照常可跑；审计面小 | `requests`（无必要）、`click`（argparse 够用）、`PyYAML`（规则用 JSON） |
| HTTP | `urllib.request` + 自写重试/限频 | 需求简单（GET JSON），可控 | 引入 `httpx`/`aiohttp`（无必要） |
| 存储 | 纯 JSON/JSONL 文件（轮次文件 + append-only 事件流） | 人可读、可 diff、字节稳定、无服务；仓库/台账可直接比对 | SQLite（二进制、字节不可比对、并发收益为零）；各种 KV |
| CLI | `argparse` 子命令 | 标准库；退出码/帮助行为可控 | `typer`/`click` 依赖 |
| 测试 | pytest（dev extra） | 生态标准；本机两通道已有 | unittest（生态弱） |
| 打包 | setuptools（`src/` 布局，PEP 621） | 标准、旧解释器兼容好 | poetry（重）、hatch（非必须） |
| CI | GitHub Actions 四矩阵（ubuntu-22.04 / windows-latest × 3.8 / 3.12），`PYTHONUTF8=1` | 覆盖编码与版本两大差异源 | 单平台单版本（覆盖缺口） |
| 分发 | GitHub 仓库 + Release（源码 + 样例日报产物） | 题面提交材料口径 | PyInstaller exe（首期不做；M6 视时间余量评估） |
| LLM | **不使用**（零 AI 接口依赖） | 判定全部走确定性规则；题面纪律 | 任何形式的"让模型猜状态/日期" |

## 四、确定性设计（"同输入→同输出"的落点清单）

1. 归一化条目键序固定（`StandardEntry.to_dict` 单一来源）；
2. 快照轮次标识递增（非时间戳），时间戳只进元数据；
3. diff/解析/迁移/倒计时全部是**纯函数**（时钟注入、无网络、无随机、禁 set 迭代序）；
4. 合成数据生成确定性（禁 stdlib `random`/系统时钟）→ 配"再生成位级一致"守门；
5. 判定语义：`pending` 是一等状态（未返回/未核对 ≠ 某个值）；**不推断、不默认填充**；
6. 一处定义：翻页/限频参数（adapters/base.py）、去抖轮数（diffing.py）、倒计时阈值（M4 落位）——文档数字一律引用代码常量，不另写副本。

## 五、跨平台与编码设计

- **输出编码三通路**（缺一不可）：
  1. 入口 `ensure_utf8_stdio()`：探针 `stream.encoding`——utf-8 不动；CJK 码页（cp936 等）保持原生编码、仅放宽 `errors`（不可编码字符不崩）；其余（cp1252/ascii）reconfigure 为 utf-8 + errors=replace；
  2. 子进程/外部命令调用一律显式 `encoding=`（不依赖 locale）；
  3. CI 全局 `PYTHONUTF8=1`（救"不是我们敲的命令"）；
- **行尾**：源码/文档 LF（`.gitattributes` + CR 守门测试）；`data/snapshots/**`、`data/fixtures/**` 标 `-text`（字节冻结，克隆后 sha256 必须一致）；
- 中文路径、Git Bash 与 Windows 路径差异：文档/脚本内路径一律相对路径；临时文件用工作区相对路径（不跨 `/tmp`）。

## 六、安全、隐私与合规设计

- 仅抓取标准**元数据**（标准号/名称/状态/日期/归口），不下载标准全文、不镜像详情页；
- 抓取限频 + UA 自标识（可被识别与联系）；遵守平台 robots；
- 纯本地运行、无遥测、无上传；快照与订阅规则都只落在本地 store；
- 全部对外产物附"以平台标准原文为准"免责声明（日报页脚固定输出）；
- 不提供"标准解读"（避免误导，非目标）。

## 七、退出码契约（K 编号引用：K2）

| 码 | 语义 | 例子 |
|---|---|---|
| 0 | 成功（含"单库失败但另一库有产出"的部分成功——原因随报告列出） | `selftest` 全过；`fetch` 双库成功 |
| 1 | 运行失败（全库失败 / 基准未达标 / 数据文件损坏） | GB、HB 都超时 |
| 2 | 用法错误（argparse 默认；未给命令也算） | 未知子命令；缺必填参数 |
| 3 | 功能未实现（骨架期桩）；或依赖/环境缺失契约 | 骨架期 `diff`；未实现模块被调用 |

发布物与 README 明示该契约；测试锁定 0/2/3 三语义（1 在 M2 起有真实用例）。

## 八、扩展接缝（留 v2，不外泄到首期）

- 适配层新增库（详情页 / 地方标准）：实现同形 `fetch()` 即接入，不动下游；
- 存储层：轮次文件格式带 schema 版本号，可写迁移脚本；
- 输出层：report 中间模型可加渲染器（如邮件/IM 适配）；
- 调度：`run` 命令设计为幂等 + 可被任何调度器（计划任务/cron）调用，无守护进程。
